# VPN 与代理：按现象排查

## 先区分两层连接

校园认证让电脑获得校园网访问能力；代理/VPN 决定之后的流量如何转发。代理节点不可用，不等于校园认证失效。JLUConnect 只管理已适配的官方登录流程，不修改代理工具。

当前诊断页只能报告系统代理/PAC 的配置状态，**不能可靠断言 TUN 是否启用、某节点是否可用、认证端点是否被正确路由**。不要将“系统代理已开启”理解为检测通过。

## 1. 官方客户端已认证，但某网站打不开

先看其他正常使用的网站或学校页面是否能打开，再检查代理软件自身的状态。单个网站故障、DNS、节点失效都可能导致这种情况。不要通过反复注销校园网来修代理，也不要断开承载远程工作或正在进行任务的网络。

## 2. 开启 TUN 后官方客户端也无法登录

记录官方错误文字，检查代理工具支持的路由、直连规则、DNS 和虚拟网卡设置。系统代理和 TUN 是两种不同的接管位置；关闭一个开关不一定关闭另一种。

如果已经有可靠资料确认学校当前使用的认证端点，可在自己工具的规则中配置**精确例外**。不要凭空猜服务器 IP、端口、协议；不要从网上抄整个私网或所有教育网的绕行规则。不同代理工具规则语法不同，本项目不提供未经验证的通用配置片段。

本版不会为了认证关闭 VPN 或改变 kill switch。企业/受管理 VPN 的阻断需要管理员允许，不能靠助手绕过。是否短暂关闭某项做对比，应由你在可接受断网风险的时间自行决定；这不是默认安装步骤。

## 3. 换机场、换节点、换代理软件

无需把订阅或密码交给 JLUConnect。只要物理校园网络和官方认证仍正常，通常无需重配助手。但更换工具可能改变 TUN、DNS、路由或系统代理残留，需重新观察官方客户端是否正常。

只有换了校园接口/网关，才需要到助手的网络设置重新识别。识别时请选物理 Wi-Fi/有线，别选隧道接口。如果不知道哪项属于校园网，暂不保存，不要尝试把所有候选都列入信任。

## 4. Wi-Fi 名称读取失败

可能涉及接口状态、系统权限或 WLAN 服务。先确认 Windows 本身能看到 Wi-Fi 名称，检查系统位置/Wi-Fi 权限提示。工具不会自动修改系统权限。读取不到 SSID 时默认不把 Wi-Fi 当成已经登记的网络。

## 反馈时提供什么

- Windows 与 JLUConnect 版本；网络类型；DrMain/DrClient 版本。
- 系统代理、PAC、TUN 哪些开启（不清楚就写不清楚）。
- 官方客户端能否手动认证，助手显示什么文字。

不要公开订阅、节点地址、认证密码、用户目录、完整网关配置、抓包、令牌或整屏截图。仅截取必要的错误文字并遮盖身份信息。
