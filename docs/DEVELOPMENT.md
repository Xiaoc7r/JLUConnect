# 开发与验证

## 构建

运行 `powershell -NoProfile -ExecutionPolicy Bypass -File scripts/build.ps1`。脚本使用系统的 .NET Framework C# 编译器，生成 x64 主程序和启动器，并运行不联网的策略测试。所有构建产物位于被 Git 忽略的 dist 目录。

安装脚本、源码和文档使用 UTF-8（PowerShell 脚本含 BOM，兼容 Windows PowerShell 5.1）。发布包有两个入口：Install.cmd 和 Uninstall.cmd；源码压缩包不等于可安装发布包。

## 状态约束

- 首次安装不包含私人网关，未登记时不自动认证。
- 只有已登记 Wi-Fi 名称/网关，或已登记有线网关，才进入认证处理。
- 网络变化先稳定等待；确认在线后不重复登录。
- 暂停跨重启保存；网络事件不解除暂停。
- 单实例、单次处理、有限重试和冷却；未知版本/提示框停止自动动作。
- 不读取密码输入框，不注册全局键盘钩子，不修改代理、路由或 DNS。

配置及有限轮转日志位于 `%LOCALAPPDATA%\JLUConnect`；日志上限按两个约 512 KB 文件轮转。无遥测。不要提交该目录，也不要把它作为 Issue 附件。

## 适配新客户端

必须先核对文件来源、PE/版本/哈希与窗口结构，再做限定验证。当前哈希白名单不是安全认证签名，也不能证明官方进程内存未被修改；它主要防止在未知版本上误操作。不要只删除白名单让程序“兼容所有版本”。

若研究 DLL，需要先确认 ABI、参数和副作用；本程序没有通用 DLL 调用器。发布二进制不能包含官方客户端 DLL 或个人 REA 输出。

## 当前测试范围

离线测试覆盖未登记禁止自动连接、Wi-Fi/网关必须共同匹配、非预期接口、列表精确匹配和暂停配置序列化。UI 预览使用合成状态，不是实网验证。

网络恢复、真实系统睡眠、权限边界和多代理组合仍需要独立实机覆盖。禁止在承载远程工作/当前开发任务的网络上进行破坏性测试；优先使用隔离机器、模拟状态或自然唤醒日志。

## 发布

main/PR 触发 Windows 构建和离线检查；版本标签触发同一构建。维护者发布前更新 AssemblyInfo 和默认版本，检查源文件与解压后的发布包是否包含私人路径、网络地址、令牌、日志或厂商程序。

发布仅包含 ZIP 与 SHA256SUMS.txt；预览版本应标记 Pre-release。源码提交使用公开的 GitHub noreply 身份，避免个人邮箱进入公开历史。若程序未签名，请如实说明，不要指导用户关闭系统防护。
